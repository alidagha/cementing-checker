# Checker working discipline — Ponytail

Read this file at the start of every Batch, then the Checker zero-regression contract and the current owner-approved scope. Understand the input-to-source-to-document chain before editing. Prefer no new code, an existing authority, then the standard library; write only the smallest necessary extension. No speculative framework, UI or integration layer.

This Checker consumes locked external engineering authorities. Never copy or rewrite their formulas, validation, source rounding, material classification or water semantics. Treat DOCX as untrusted claims; independent operator inputs are the reference. Preserve ambiguity, original locators and all unresolved claims. No overall engineering PASS.

An approved bounded task determines writes and tests. Original App, accepted ancestors and private recovery remain read only unless a later exact authorization says otherwise. No dependency/environment/Git/publication change is implied by a local task. Never edit a test to manufacture green. Record real commands, costs, hashes and limitations. Read the complete applicable upstream AGENTS/contract and rev8 Charter privately before engineering work; public references are in `docs/governance/authority.md`.

New tests need ordinary discovery, exactly one whole-module A/B/C assignment and a reproducible final schedule-byte SHA256. Run the smallest meaningful controls, preserve failed attempts and obey the Charter cost/retry gates. Publication, hosted CI and protected-main configuration require separate Owner authorization. No STATUS.md unless requested.
