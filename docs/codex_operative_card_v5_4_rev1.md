  * **Outcome 3 — Cause Still Ambiguous:** Run another different, authorized diagnostic if the 3-attempt and 20-minute budgets allow; otherwise **STOP** with one consolidated ruled-in/ruled-out account. Never click blindly or fabricate a browser action/receipt.

## 3. Permanent Non-Waivable Protections

* **Engineering Lock:** Never implicitly alter formulas, constants, SG, units, tolerances, limits, rounding, calculation order, rheology, blend/material classification, placement, defaults, canonical precision, review/lab signatures, validation, source rounding or water semantics of the locked upstream authorities. Never add a physical limit, compatibility rule, validation or formula, and never guess engineering data; unapproved engineering decisions are a **STOP**. Analyzing risks is permitted.
* **Checker Semantics Lock:** DOCX is untrusted claims; independent operator inputs are the reference; preserve ambiguity, original locators and unresolved claims; missing/zero/dash/N/A/malformed/ambiguous stay distinct; unsupported association fails closed; independent Client Requested Volume; pure Mix Water vs. total preparation water; original DOCX bytes never rewritten (corrections only to a new private copy of explicitly selected, source-proved cells); **no overall engineering PASS**.
* **Fixture Rule:** Build fixtures in this order: `valid source/state prerequisites -> validated measured rows/QC -> genuine review/source signatures -> current dependent calculations -> original assertions`. Valid fixtures contain only explicit, valid synthetic data; invalid/stale fixtures must stay fail-closed; a cached payload, forged signature or stale seed is never approval. Never change production validation to make a fixture green; never let one error shadow an independent one.
* **UI Design Lock:** No unapproved UI redesign, new fields, buttons, tables, captions, help panels, layout shifts or surrogate workflows; if approved behavior cannot be preserved, STOP and present options. Within an Owner-approved existing-control reliability Batch, minimal repairs of that control's already specified selection, commit/blur/Enter sync, numeric typing, row add/edit/delete, row identity, stale-result invalidation and typed payload delivery are permitted. **No silent feature expansion:** an editor-verification authorization never extends to C09/G06 UI binding, 15-case Golden acceptance, automatic correction scope, source-reference semantics or production-release claims.
* **Zero Fake-Green Tolerance:** Never delete, skip (`pytest.skip`), `xfail`, disable assertions, broaden exception catches, weaken Permanent Guardrails, or use temporary `PYTHONPATH` / unauthorized `sys.path` hacks. Never modify a workflow to ignore a shard, suppress warnings, shrink discovery, or weaken the `regression` gate.
* **Verification Level:** Any touch—even one line—to engine comparison logic, a shared helper, schema, trust boundary, protected tests/guardrails or sensitive validation requires **FULL** targeted verification (call graph + all consumers + sibling modules), not a local full-repository regression. Only a purely local display change with zero shared/protected effect may use LIGHT. Never call a timeout or flaky failure a PASS.
* **Environment Non-Equivalence:** Streamlit `AppTest` ≠ real Chromium; DOM observation ≠ authenticated backend admission; synthetic source-rendered DOCX ≠ real App-generated Golden; LibreOffice/PDF ≠ native Word; Merge ≠ Production Deployment. Real-browser verification of Streamlit UI uses `.codex/skills/streamlit-browser-testing`; a control the browser never reached is `NOT_VERIFIABLE`.
* **Runtime & Distribution Isolation:** Caches, temp files, upstream snapshot and generated fixtures live only in the private runtime outside the repo and every Git worktree. Never commit the upstream App, Word template, libraries, original fixtures, DOCX files or recovery archives.
* **Repository Separation:** `Cementing App` and `Cementing Checker` are strictly separate scopes and dependency locks.
