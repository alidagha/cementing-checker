## What admission can prove

An external DOCX with plausible sections, correct-looking source/template hashes or
a list of claimed function names cannot prove its own generation history.
`inspect_external` checks integrity/structure and always withholds authentic admission
without a fresh legitimate production execution. Unknown/duplicate headings,
unsupported numbering/fields/hidden text, damaged input, hash or private-path mismatches
fail closed. It never rewrites the original. A redaction helper is not a verifier:
`public_metadata` cannot authenticate a caller-created dictionary or confer authority.

`generate(reference)` accepts only `{kind, project}` with `kind` explicitly
`SYNTHETIC_TEST_INPUT` or `INDEPENDENT_PROGRAM_INPUT`. The canonical JSON digest binds
that declaration and its inputs. Classification alone never proves a measured result
or approval. No expected value comes from the Word candidate.

A fresh separate subprocess verifies all source hashes/blobs and accepted locks,
uses a real isolated Streamlit ScriptRunner/SessionStateProxy, and installs only
independent canonical inputs. Source DataFrame column names are preserved. It calls:

1. `phase_10_procedure.build_master_context()` with its default full calculation,
   review and export gates (never `calculations_prepared=True`).
2. Original pumping/schematic consumers and `DocxTemplate` render using the actual
   returned master context and original `_word_quantity_context`.
3. `well_report.postprocess_well_report`, with the original context's well profile,
   vertical NOTE, cement chart, centralizer and source pumping/schematic outputs,
   following the real phase_10_procedure Build Word caller (2038–2063 at the lock).

No hand-crafted report context or `render_*` control qualifies. Actual call tracing,
143-file verification, module SHA256s, input/template/document hashes and stage/error
are retained privately. Source modules must resolve in the verified snapshot.
Network is denied; writes stay in private runtime tmp/cache. Accepted engine/parser
files are unchanged. A gated failure creates no document and is GENERATION_BLOCKED.

Caller-supplied review/cache/signature fields are rejected, including nested QC flags.
`project_state.refresh_lab_payloads` (710–805) requires current formulation/conditions,
complete Lab rows, rheology/collection/thickening/compressive observations and genuine
review signatures. The Phase VII source button at 739–743 explicitly confirms that
values are **measured and checked**. G03 does not set those flags, manufacture signatures,
invent measurements, click approval for unobserved data or bypass the gate. Existing
synthetic C07/other component controls do not supply independent observed/reviewed
production evidence. Excluded charts/schematics may still be App export prerequisites;
Checker exclusions do not authorize bypassing them.

If all original gates genuinely pass, a worker-produced report earns only
SOURCE_GENERATED_SYNTHETIC or SOURCE_GENERATED_CANDIDATE, conditional on its declared
input kind. Successful complete production generation is not yet demonstrated by
G03-A. Replay of a legitimately reviewed live App session and independent observed
Lab evidence remains a G03-B prerequisite, not a JSON-flag workaround. No current
code path promotes to PARTIAL_VERIFIED without a separate evidenced parity pack.
GOLDEN_PASS is forbidden in G03: v3.3 F/G require corrected-copy recheck and accurately
retained unselected discrepancies, deliberately out of scope.

availability is UNAVAILABLE and generation NOT_RUN at the G03-A checkpoint; it is
not fifteen executed Goldens. Later feasibility attempts/blockers belong in the

identities and SHA256 metadata may be published. Private operator/project files,

exception stays private; only ORIGINAL_APP_EXPORT_GATE is publicly summarized.
Historical seven Word examples and Squeeze PDF remain references, not Goldens.
